# Manual MQTT two-host harness (WL-15 Q11)

Test tooling for the manual evidence run required by WL-15 Phase 5. Nothing here
is part of the Rust build, the CI matrix, the automated test suite, or the
release package. The repository ships no broker and no credential.

- `mqtt_peer.py` — a small MQTT 5 peer host that subscribes and publishes over
  TLS, with optional client-certificate authentication. Requires `paho-mqtt`
  2.x on the peer host only.
- `mosquitto-tls.conf` — a Mosquitto listener configuration with TLS on the
  primary host. Mosquitto is the accepted manual broker only; it is not a
  supported product surface.

## Procedure

Material (generated by the operator, never committed): a CA file, a broker
server certificate and key, optional peer client certificate and key, and the
optional Mosquitto password/ACL files.

1. Primary host: start the broker and record its version.

   ```bash
   mosquitto -h
   mosquitto -c tools/mqtt/mosquitto-tls.conf -v
   ```

2. Primary host: build and run the runtime against the broker, with `-v` so the
   `io-backend mqtt` line is printed.

   ```bash
   stc build
   stc run -v
   ```

3. Second host: peer evidence.

   ```bash
   python3 -m pip install --user 'paho-mqtt>=2,<3'
   python3 tools/mqtt/mqtt_peer.py subscribe --host <primary> --port 8883 \
       --ca io/ca.pem --cert io/peer.pem --key io/peer.key \
       --topic 'line1/plc/#' --timeout 120
   python3 tools/mqtt/mqtt_peer.py publish --host <primary> --port 8883 \
       --ca io/ca.pem --topic line1/plc/cmd/start --message 1 --retain
   ```

4. Cover the required observations: subscribe, publish, retained replay (a new
   subscriber receives the retained value), last will (stop the runtime
   without a clean shutdown and observe `line1/plc/status`), reconnect (restart
   the broker and watch `client0.reconnects` advance), stale inputs, the TLS
   session, an MQTT 3.1.1-only broker rejection, and a bad-credential failure.

## What the verification report records

- Broker name and version, TLS version and cipher from the broker log.
- Material **paths only**, never contents or fingerprints.
- The peer-script revision (`git rev-parse --short HEAD`).
- The commands above and their output, including the `stc run -v` line and the
  peer transcript.
- Host names, OS versions, and whether client-certificate authentication was
  enabled.

This run is manual by design and is never presented as a CI result.
