M6.5 sits between M6 and M7. It implements the full v1 debug/monitoring surface on the host/module
architecture from M4.5. It assumes online change is working; every swap must end a debug session
cleanly.

The M4.5 substrate this plan extends is recorded in
[Debug and Monitoring](Specification/Architecture/Debug-and-Monitoring.md) §12: stable
`GotId`/manifest/layout identity, active-root access, generation pins, descriptor debug feature
bits, append-only ABI 2 services, trap records, and the swap/rollback boundary are available;
checkpoint emission, DWARF/CodeView, typed access, write/force queues, and the debug session
protocol are not. Phase 2 below adds the checkpoint table and host calls, phase 1 the debug
information, and phases 3–8 the services and session.

**M6 boundary (2026-10-27):** M6 is complete and kept descriptor/manifest format 1 and host ABI
major 2 (phase 4 later raised only the GOT manifest to format 2 under D-180). It appended exactly one service — host ABI 2.2, ID 12, `set_cycle_time_ns(int64_t)`, for
test builds only — and added no debug information, checkpoint hook, debug service, or
service/monitor thread. The `stc run --watch` control channel is local deployment/status only
and is not the debug protocol; M6 added the control/status thread and kept candidate
validation/load/prepare on the cycle thread. M6.5 therefore appends debug services starting at
ID 13, never changes service 12 or an earlier signature, and owns `--release`, DWARF/CodeView,
checkpoints, typed access, forcing, breakpoints, stepping, sessions, and their
authentication/audit. This plan assumes that boundary; if a later M6.5 phase needs another
service, it must record a new decision and re-open §12 of the debug specification.

## 1. Objective

Deliver local, authenticated, typed debug and monitoring for v1:

- typed read/write/watch of persistent and local variables by path/`GotId`;
- forcing applied at cycle boundaries and held until release;
- codegen breakpoint checkpoints, stop-the-world stepping, and call-stack inspection;
- full DWARF/CodeView debug information by default, with `--release` as the stripped/optimised
  mode;
- a manifest-assisted split-object view that reflects per-field roots and handles;
- a documented session model with a stop/idle bound (watchdog pause when a watchdog exists),
  output hold, audit, and swap teardown.

## 2. Scope

### 2.1 In scope

| Area | Work |
| --- | --- |
| Access | Typed path/`GotId` read/write; generation pinning; removed-field rejection |
| Watch | Polling/streamed typed values tagged with generation and cycle |
| Force | Boundary-applied typed overrides; release/session-end/swap teardown; audit |
| Breakpoints | Codegen checkpoint table; source-location binding; stop/continue |
| Stepping | Stop-the-world step over/into/out; optimized-out reporting |
| Call stack | Frame unwinding with function identity, source location, typed locals where available |

| Split view | Manifest-assisted per-field/object view; clearly labelled |
| Protocol | Local pipe (default) or socket; authentication/authorization; rate limits/timeouts; audit |
| Session | Start/stop, stop/idle bound, output hold, swap teardown, force/breakpoint clearing |
| CLI | `stc debug`, debug build options, status/diagnostic output |
| Builds | Debug default; `--release` distinct build ID/manifest; no hooks in release |
| Tests | Both hosts; access/force/breakpoint/step/stack/info/session/swap/security |

### 2.2 Out of scope

- Safety functions or certification. The project is not a safety PLC and assumes no safety
  responsibility; debug may hold outputs indefinitely.
- Remote/network debugging and multi-user sessions.
- Raw-memory read/write in the standard API.
- Persistent breakpoints/forces across swaps or restarts.
- Reconstructing missing source/debug information from a manifest.
- A general-purpose profiler or trace analyzer (future tooling).

## 3. Exit criteria

- Typed read/write/watch works for scalars, aggregates, strings, interfaces, direct variables,
  and locals in a stopped frame.
- A write/force queued across a swap is rejected or retried against the new generation; it never
  targets a removed field.
- Forcing is applied at the cycle boundary, held until release, and cleared at session end/swap.
- Breakpoints bind to codegen checkpoints; unbound locations are reported, not moved silently.
- Step/continue and call-stack unwinding work in debug builds; optimized-out frames/variables are
  reported honestly.
- DWARF/CodeView resolves variables/source locations under platform tools on Windows and Linux.
- Debug information is the default; `--release` produces distinct build IDs/manifests and no
  debug hooks.
- Starting a session does not stop the cycle; a stop holds outputs and is bounded by the
  documented stop/idle budget; stopping/disconnecting resumes normal policy.
- Every online swap ends the session and unloads the old generation.
- Authentication/authorization, rate limits, timeouts, and audit are implemented and tested.
- Debug-disabled overhead is measured and documented; release artifacts are clean.

## 5. Compiler work

- Emit full DWARF/CodeView for variables, types, fields, source locations, and frames through
  clang. Paths and type/field ordering are deterministic; no timestamps.
- Link debug info to manifest identities where useful for the split-object view; do not make the
  debugger depend on the manifest for basic source-level debugging.
- Emit a checkpoint table at eligible statement/block boundaries and calls to a host check. The
  host decides whether a checkpoint stops; release builds omit the table and calls.
- Preserve source spans for traps and debug locations; keep span IDs stable within a build.
- Emit distinct build IDs/manifests for debug and release. Release may emit a sidecar symbol file
  without changing runtime behaviour.
- Do not patch machine code for breakpoints.

## 6. Runtime and host work

### 6.1 Typed access

- Resolve typed path/`GotId` through the active manifest/root registry; reject raw addresses.
- Pin the active generation for the duration of a read; never take a cycle-blocking lock.
- Read atomic roots as a unit; report generation/build ID/cycle with each result.
- Reject writes to removed fields or changed layouts. Apply writes/forces at the cycle boundary.

### 6.2 Forcing

- Apply after normal cycle writes and before output publication.
- Hold until release, session end, or swap; do not persist to the state file.
- Record target/value/time/session/release in the audit log.
- Forcing an input affects the next cycle; forcing an output holds the published value subject to
  the I/O backend.

### 6.3 Breakpoints and stepping

- Match source locations to checkpoints in the active generation; report unbound locations.
- Stop the cycle thread before the checkpoint statement; resume on continue/step.
- Enforce the documented stop/idle bound; terminate the session on expiry.
- Step over/into/out; a step across a swap ends the session.
- Unwind frames using debug info; mark optimized-out values rather than inventing them.

### 6.4 Session and protocol

- Local transport: named pipe by default; local socket optional. This is a separate endpoint and
  protocol from M6's `stc run --watch` deployment/status control channel (D-155); the two do not
  share messages, authentication, or a port/name.
- Authentication/authorization for debug and force operations; rate limits and request timeouts.
- Audit connect/disconnect, protected reads, writes, forces, breakpoint changes, stops, and
  termination.
- No raw-memory API in the standard mode. A privileged raw-memory mode, if ever added, is a
  separate product decision.
- Session end: clear breakpoints/forces, resume the cycle/normal output policy, release pins.
- Online swap: end the session, clear state, drop old debug info after unload, require reconnect.

## 7. Non-safety behaviour

The runtime may hold outputs indefinitely while stopped or forced. There is no automatic
fail-safe, output timeout, or safety interlock. Documentation and CLI output must state this
explicitly; the project is not a safety PLC and assumes no safety responsibility.

## 8. Test plan

- Typed reads/writes for scalar, aggregate, string, interface, direct-variable, and local targets.
- Removed-field/changed-layout rejection across a swap; write/force retry/reject behavior.
- Watch coalescing, rate limits, and generation/cycle tagging.
- Force apply/release/teardown; no state-file persistence.
- Breakpoint bind/unbind, stop/continue, step over/into/out, call-stack unwinding, optimized-out
  reporting.
- DWARF/CodeView inspection on Windows and Linux; debug/release build-ID and hook checks.
- Pause-bound expiry/resume, output hold, session end, swap teardown.
- Authentication/authorization failure, rate-limit timeout, audit completeness.
- Split-object view with per-field roots/handles; label correctness.
- Release overhead measurement with debug disabled.

## 9. Risks and mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Debug hooks perturb timing | Cycle jitter | Release omits hooks; measure overhead; keep checkpoints cheap; document |
| Holding outputs mistaken for safety | Unsafe user expectation | Explicit non-safety stance; CLI/documentation warnings; no fail-safe claim |
| Stale descriptor after swap | Crash or wrong variable | End session on every swap; generation pinning; drop old info after unload |
| Optimized variables unavailable | Misleading debugger | Report optimized-out; debug build is default |
| Protocol exposure | Unauthorized access/forcing | Authentication/authorization, rate limits, audit, local-only transport |
| Debug info non-determinism | Irreproducible builds | Deterministic paths/order; no timestamps; build-ID/manifest separation |

## 10. Definition of done

- All §3 exit criteria pass on Windows and Linux.
- Debug and release artifacts are distinct and correctly stripped/hooked.
- The non-safety behaviour is documented and visible in CLI output.
- M7 can treat debug/monitoring as a hardened, tested capability.

### Phase 0 — design contracts (2026-10-27)

Completed as a documentation-only phase; no Rust or artifact changes. Fixed for implementation:

- **Protocol** (Debug and Monitoring §13, D-173–D-174): local `stc-debug/1`, pipe default and
  loopback socket optional, LF-delimited JSON, 1 MiB request / 4 MiB response and event limits,
  one outstanding request with widening IDs, error object shape, token authentication, the
  `observe`/`control`/`write`/`force` scopes, protected-data auditing, fail-closed audit, and no
  raw-memory API.
- **Session lifecycle** (§14, D-175): one session per host, stop parks the cycle in host service
  13 and holds the last output image, documented `[debug].session-timeout` stop/idle bound
  (default 5 min), generation/build/cycle tagging, teardown on swap/disconnect/timeout, and
  explicit reconnect.
- **Typed access** (§15, D-176): path/`GotId` resolution, generation-pinned atomic reads,
  per-leaf split aggregates, removed-field/stale-generation rejection (`STC-E-DEBUG-010`), a
  cycle-boundary write/force queue ordered after the module cycle and before output publication,
  release at the boundary, and watch limits/coalescing.
- **Checkpoints** (§16, D-177): dense checkpoint table, source-span binding, service ID 13
  `debug_check(uint32_t, uint32_t)` appended at ABI minor 3, entry bit 6 iff required-feature
  bit 4, release/test hook-free.
- **Builds** (§17, D-178): debug is the default build, `--release` semantics, distinct build
  IDs/manifests, deterministic DWARF/CodeView, sidecars, and mode-specific default out-dirs.
- **Diagnostics** (§18, D-179): stable `STC-E-DEBUG-001`–`022` and
  `STC-W-DEBUG-001`–`005`, indexed in the Conformance Profile §10.1 and allowlisted as
  `not-implemented` until phases 3–8.
- **Contracts for later phases**: CLI and Manifest §1.7/§2.2 (`stc debug`, `--debug-protocol`,
  `--debug-server`, `[debug]` keys), Runtime and Execution host options, GOT Artifacts ABI 2.3,
  Online Change and GOT session/swap rules, Testing and Verification §4.2.

Deviations recorded:

- The checkpoint table lives in the additive `debug` object of `<name>.stc-meta.json`, not in a
  module export, section, descriptor, or manifest. Adding a module section would change module
  format 1, so generated code carries only inline `(checkpoint_id, span_id)` calls.
- No watchdog exists in M6. Phase 6 implements the documented stop/idle budget; phase 9
  records the overhead. The cycle deadline is reset on resume.
- Test builds stay debug-form (entry bit 4) but hook-free (bit 6 clear, required feature bit 4
  clear, ABI minor 2), preserving the M6 test ABI.
- `[build].debug` is canonical and must agree with an explicitly present `[debug].default`;
  CLI `--debug`/`--release` override both, and both flags together are `STC-E-PROJECT-010`.
- Default out-dirs are `target/stc/debug` and `target/stc/release`; an explicit out-dir is used
  verbatim for either mode, and using one explicit directory for both modes is unsupported.

No open blocking questions. Later phases must keep the diagnostics, protocol, and schemas above
stable and append their own status entry.

### Phase 1 — compiler debug-info emission (2026-10-27)

Completed compiler-side DWARF/CodeView emission behind the existing
`stc_codegen::Options.debug` flag. The CLI default, artifact formats, ABI, and debug/release
split are unchanged; phase 2 still owns the default flip, `--release`, checkpoints, and host
check calls.

- **Real source locations.** `DISubprogram`, `DILocation`, and `DILocalVariable` nodes come from
  `SourceMap` byte spans, with line and column computed from the source text. Files are emitted
  as package-relative, forward-slash `DIFile` paths with directory `.`; no host path, timestamp,
  or synthetic line/column zero is emitted. Functions without a real user source span (interface
  trap stubs, standard FB bodies, the synthetic launcher) carry no debug metadata.
- **Language surface.** User functions, program bodies, FB bodies, and methods get
  `DISubprogram` metadata; parameters and locals use `DILocalVariable` plus `llvm.dbg.declare`;
  globals, program fields, and retained roots use declaration-only
  `DIGlobalVariableExpression`. Scalars, enums/named values/subranges, structs, FBs, classes,
  interfaces, static and conformant arrays, strings, references, and pointers are emitted as DI
  types with named fields and correct sizes/offsets. `DICompositeType.identifier` carries
  `stc:T:<GotId hex>`, and `DIGlobalVariable.linkageName` uses the GOT symbol, linking type and
  variable identities to the existing artifact identities without making debugging depend on
  the manifest.
- **Determinism.** Nodes are allocated in a fixed reserve/allocate order, ordered maps/sets are
  used throughout, paths are normalized to package-relative forward-slash form, the producer is
  only `stc <version>`, and metadata is rendered in node-ID order. Module flags select DWARF 5,
  Debug Info Version 3, and `wchar_size` 2 for ELF targets, or CodeView 1 with Debug Info Version
  3 and `wchar_size` 2 for MSVC targets.
- **clang wiring.** The driver passes `-g` only when the build request has debug enabled:
  `-gdwarf-5` for ELF and `-gcodeview -gno-codeview-command-line` plus
  `-Xclang -object-file-name=<basename>` for Windows, with `-fdebug-compilation-dir=.` on both
  so emitted paths stay relative. With `debug: false`, no debug flags or metadata are emitted
  and M6 IR/object output remains byte-identical.
- **Tests.** Added six IR/object tests in `crates/stc-codegen/tests/debug_info.rs` covering
  metadata presence and absence, real file/line/type/field content, path normalization and
  determinism across host paths and output directories, and object inspection. Windows checks
  use `llvm-pdbutil` and `llvm-readobj --codeview`; Linux checks use
  `readelf --debug-dump`, `llvm-dwarfdump`, and `llvm-objdump --dwarf`. The driver CLI test
  verifies default builds have no debug metadata and a `--debug` build emits inspectable object
  debug sections. Runs with `STC_REQUIRE_CLANG=1` in the full workspace suite.

Deviations and limits recorded:

- Persistent globals and program fields live in host-owned GOT storage, so debug metadata has
  no honest module storage location to attach. They are emitted as declaration-only global
  variables: DWARF exposes their name, type, and source declaration; CodeView emits only
  defined globals and therefore omits them. Source-level function, local, parameter, and type
  debugging does not depend on these nodes. Phase 3 typed access and phase 7 split-object views
  supply live values and addresses from GOT/manifest identities; phase 5 sessions own the PDB
  and sidecar story.
- No debugger runtime, protocol, checkpoint table, host check call, typed access, forcing,
  session, or `stc debug` CLI work was added; descriptor and module format 1 (and, at phase 2,
  the manifest/binary/JSON format 1) and the host ABI, service IDs, build-ID artifacts, and
  entry/required-feature bits are unchanged. Phase 4 later raised only the GOT manifest to
  format 2 (D-180).
- No specification text change was required: §17.3/§17.4 already require DWARF/CodeView,
  deterministic relative paths, and no timestamps. Declaration-only GOT variables are a
  phase-boundary limitation, not a format clarification. Phase 2 can emit checkpoint calls as
  ordinary instructions and reuse `Function::set_debug_location`/`debug_declare` so the calls
  inherit real source locations.

### Phase 2 — checkpoint table and host check calls (2026-10-27)

Completed the compiler checkpoint table, the append-only host ABI 2.3 service, and the
debug/release split.

- **Checkpoint collection.** After lowering, debug builds collect statement entries, the first
  executable statement of each IF/ELSIF/ELSE, CASE arm, and loop body, each call site immediately
  before the call, each loop back-edge, and each RETURN. Empty statements, empty spans,
  unreachable blocks, generated/synthetic function bodies, and expression-level sites without a
  real call are excluded. Sites carry the phase-1 source span, real 1-based line/column,
  function `GotId`, and flags bit 0 statement / 1 block entry / 2 call / 3 loop back-edge.
- **Dense IDs and calls.** Sites are sorted by `(function GotId bytes, span start, span end,
  flags, source order)` and assigned dense IDs from 1; ID 0 is never emitted. Three ordinary IR
  instructions (`getelementptr`/`load` of the service-13 import cell, then the indirect call) are
  inserted at the recorded program point, so the hook executes immediately before the site. A
  debug build with no eligible sites re-projects the GOT hook-free, keeping the descriptor,
  manifest, and metadata consistent.
- **Sidecar and descriptor.** The additive `<name>.stc-meta.json` `debug` object format 1 carries
  `build_id`, `format`, `hooks`, `info` (`dwarf`/`codeview`/`none`), and checkpoints sorted by
  ID with `id`, `span`, function `GotId` hex, 1-based `line`/`column`, and `flags`; limits are
  1,000,000 entries and 64 MiB. The object is not an input to build-ID, manifest, or
  online-change identity. `required_features` bit 4 and `entry_flags` bit 6 are set exactly when
  at least one checkpoint was emitted and service 13 is imported; such modules require host
  minor 3. Every debug-form build sets `entry_flags` bit 4; release clears it.
- **Host ABI 2.3.** The runtime appends `debug_check(uint32_t, uint32_t)` as service ID 13 after
  `set_cycle_time_ns`; the version word is `0x0002_0003` and the struct-size/minor gate is
  unchanged. The service is a lock-free, allocation-free no-op without a session and is the
  documented phase-6 stop/park and breakpoint-matching hook point. Descriptor validation rejects
  disagreeing hook bits, a feature/import mismatch, or hooks below minor 3 with
  `STC-E-MODULE-002`; older 2.2 hosts reject 2.3 modules, and 2.3 hosts still load 2.1/2.2
  modules. Module metadata parsing exposes the raw additive `debug` object but never requires it
  for ordinary loading.
- **Debug/release split.** Precedence is CLI `--debug`/`--release` (mutually exclusive;
  `STC-E-PROJECT-010`), then explicit `[build].debug`, then explicit `[debug].default`, then
  debug. Explicitly present conflicting manifest settings are `STC-E-PROJECT-010`. Debug is the
  default form with opt-level 0, debug info, checkpoints, service 13, descriptor bit 6/feature
  bit 4, and host minor 3. `--release` is optimized (default opt-level 2), stripped, hook-free,
  emits no checkpoint table/debug object/`debug_check` import/debug sections, clears bits 4/6,
  requires minor 2.1, and derives distinct build-ID/manifest identities through generator-flags
  bit 1. Default out-dirs are `target/stc/debug` and `target/stc/release`; explicit
  `[build].out-dir`/`--out-dir` is used verbatim and mixing modes in one explicit directory is
  rejected. Release artifacts are stripped with `llvm-objcopy`/`objcopy --strip-debug`, which
  preserves the build-ID note, descriptor, manifest, and metadata. `stc clean` and
  `stc clean --release` select the matching default directory. `stc metadata` appends
  `build_mode`, `debug_info`, and `debug_hooks` to both summary forms. `stc test` remains the
  hook-free debug form at ABI 2.2 and rejects `--release`, `--debug-server`, and
  `--debug-protocol`; `stc build`/`run`/`online` accept both modes; `stc debug` and the session
  protocol remain unimplemented.
- **Tests.** Added codegen checkpoint snapshots and eligibility/order/ID/determinism tests
  (`crates/stc-codegen/tests/checkpoints.rs`, `tests/snapshots/checkpoints.json`), runtime
  ABI 2.3 shape/no-op/version/hook-bit tests, and driver tests for host-visible hook bits,
  release stripping and identity, opt levels, out-dirs/mixing, mode precedence and conflict
  diagnostics, clean mode, metadata summary fields, session-flag rejection, and hook-free ABI
  2.2 test builds. Existing M6 snapshots remain unchanged unless their build form changed
  (default debug is now expected).

Deviations and limits recorded:

- Windows DLL/PDB production remains phase-5-owned: objects carry `.debug$S`/`.debug$T`, but the
  current `lld-link` invocation without `/DEBUG` does not put CodeView into the DLL. Phase 2
  verifies checkpoint hooks and release absence through the descriptor, sidecar, IR, and object
  sections without claiming a DLL PDB.
- Release builds require `llvm-objcopy` or `objcopy` (beside clang or on PATH). This is a
  toolchain prerequisite, not a new dependency.
- A release static embedding host library is a direct copy of the runtime toolchain archive.
  `llvm-objcopy`/`objcopy` do not support `!<arch>` archive containers, so those copied bytes
  are left unchanged (the module, object, and executable are still stripped). Package a runtime
  archive built without debug information when the embedding library itself must be debug-free.
- An explicit out-dir containing only `--emit ir` output cannot reveal its build mode, so mixed
  modes are detected from paired manifests or metadata sidecars; the documented supported use is
  distinct out-dirs per mode.

### Phase 3 — host typed access, read side (2026-10-27)

Completed the host-side target, typed-value, read, watch, and service-queue models for Debug and
Monitoring §15.1, §15.2, §15.5, §15.7, and §15.8. Writes and forces remain phase 4; protocol,
sessions, authentication, audit, and rate limiting remain phase 5.

- **Targets and resolution.** `DebugTarget` carries a stable path, a `GotId`, or a stopped-frame
  local. Paths are normalized by case-folding each identifier segment while preserving package
  (`PKG::`), program/instance (`.`), and instance qualifier (`#CFG/RES/INST`) structure. Raw
  addresses, offsets, pointer expressions, empty segments, and malformed keys are rejected as
  `STC-E-DEBUG-008`. Resolution checks target shape, existence, expected generation/build,
  expected type/layout, and (for later writes) writability in that order. Unknown targets are
  `STC-E-DEBUG-008`; removed/renamed targets and expected generation/build/type/layout mismatches
  are `STC-E-DEBUG-010`. An unqualified path never silently moves to a same-named field in
  another instance: prior keys, retired records, and plan actions with a different non-hidden
  qualifier make it stale. Locals are read only from an immutable stop-frame snapshot; a missing,
  mismatched, or stale frame is `STC-E-DEBUG-015`, an unknown local is `STC-E-DEBUG-008`, and an
  optimized-out local is returned as unavailable with `STC-W-DEBUG-002`.
- **Reads and typed values.** `Host::debug_read` pins the active generation, resolves against the
  active manifest, copies from persistent/direct storage, and drops the pin. It never takes the
  host control lock across a copy. Scalars, enums, subranges, time/date values, single-root
  strings, and single-root scalar arrays are one atomic copy (`atomic:true`); an `OVERLAP` value
  is its declared bytes in base64. Split aggregates, class/FB objects, interfaces, and references
  are manifest-assisted leaf views with `atomic:false`. All leaves of one read come from one
  pinned boundary, so the result reports `consistent:true`; the per-value watch envelope carries
  the same flag for later coalesced views.
- **Encoding.** The host typed model is `DebugValue::{Bool, Decimal, Real, String, Array,
  Aggregate, Object, Reference, Overlap, Unavailable}` with a canonical type key. Integers use
  decimal strings, finite reals use JSON numbers, non-finite reals use the host `f64` values for
  phase 5 to render as `NaN`/`INF`/`-INF`, strings carry capacity plus code-point units and
  validated text, arrays are in declared index order, references/objects expose an opaque
  `0x<16 hex>` identity and never an address, and unavailable values carry a warning. Storage is
  checked against the computed manifest layout; wrong width/shape, over-capacity strings,
  malformed surrogate sequences, and inconsistent overlap/array storage are
  `STC-E-DEBUG-009`.
- **Watches and service handoff.** `DebugService` is `Send + Sync` and only queues commands and
  drains events; it never dereferences host, module, root, or process-image storage. The cycle
  thread applies queued reads/watches through `Host::debug_pump_at` at the next boundary while
  holding a generation pin. Watches are capped at 256 targets with a 50 ms minimum, coalesce
  missed periods into one batch, and report per-value generation/build/cycle/atomic/consistent
  fields and per-value `STC-W-DEBUG-002`. The event queue keeps at most 64 watch batches or about
  1 MiB, evicts the oldest watch batch and marks the next batch `STC-W-DEBUG-003`, and never
  evicts read/error state events. A generation change (cold install, activation, rollback, or
  shutdown) ends all watches; phase 5 wires the session end. Protected-data watch audit and
  add/remove policy remain phase 5.
- **Tests.** Added 17 unit tests for normalization/resolution, `GotId` strictness, removed and

Deviations and limits recorded:

- At phase 3, manifest format 1 had no enum member set or subrange bounds, so a read could

  value at read time; it did not invent a range or reconstruct a value. Phase 4's format-2

- At phase 3, a whole program instance and an array-of-aggregate element's parent shape had no

### Phase 4 — manifest type metadata, write/force queue, boundary, audit (2026-10-27)

Completed the host write/force path for Debug and Monitoring §13.3, §15.3, §15.4, §15.6, and
§15.8, and reopened the GOT manifest only for the type metadata that phase 3 could not represent
(D-180). Session/protocol, authentication, audit-file I/O, rate limiting, breakpoints/stepping,
split-object presentation, and the CLI remain later phases.

- **Manifest format 2.** `MANIFEST_FORMAT` is 2, the canonical JSON outer format is 2, and the
  manifest and catalog digest domains are `stc:manifest:v2` and `stc:catalog:v2`; the build and
  plan domains stay `stc:build:v1` and `stc:plan:v1` because their encodings are unchanged.
  Required sections tag 12 `TypeMetadata` and tag 13 `Aggregates` carry enum member sets,
  subrange bounds, and type/program split shapes. Type metadata exists exactly for enum and
  subrange types; members are normalized, unique, and sorted by `(value, name)`, and bounds
  satisfy `lower <= upper`. Type aggregates have no qualifier or fields and require split roots;
  program aggregates match their instance program type, carry the instance qualifier, and list
  canonical top-level fields with roots. Both sections round-trip in binary and canonical JSON,
  are covered by `catalog_digest` and the build ID, and are validated on decode. A format-1
  outer manifest is rejected with a version error and selects cold download; it is neither
  upgraded nor partially read. The descriptor, module, state, metadata sidecar, host ABI, and
  entry-point formats stay unchanged; only the descriptor's `manifest_format` field is 2 and
  pairs only with a format-2 manifest.
- **Codegen projection.** `stc-codegen` projects `NamedType.enum_values`/`subrange` and the
  catalog's aggregate declarations into the new records, sorting type metadata by type identity,
  enum members by `(value, name)`, aggregates by package/path/qualifier, and program fields by
  path. `stc-got` owns the binary codecs, canonical JSON projection, catalog/build digests,
  validation, and old-format rejection; the runtime manifest store/loader and descriptor pairing
  consume the same format constants. Fuzz seeds add a valid format-2 binary and JSON manifest and
  keep format-1 seeds as negative inputs.
- **Typed-read completion.** Whole-program instance aggregates and array-of-aggregate elements
  now resolve through their aggregate records and return their fields instead of
  `STC-E-DEBUG-008`; split values remain non-atomic per-leaf views. Ambiguous or absent shapes
  are still rejected rather than guessed.
- **Write and force queue.** `Host::debug_enqueue_write` and `Host::debug_enqueue_force` resolve
  a path/`GotId` target against the pinned active generation, reject locals/parameters, task
  guards, class/interface identities, `REF_TO`/`POINTER` values, `OVERLAP` roots, split-parent
  values, and fields without their own persistent root, and validate exact declared type, enum
  membership, subrange bounds, integer range, array shape/count, string capacity/units, storage
  size, and (for direct variables) the active process-image binding before enqueue. A request
  gets a server-assigned `queue_id`; limits are 1024 entries or 1 MiB (`STC-E-DEBUG-011`), and
  there is no implicit conversion. Expected generation/build/type/layout mismatches are
  `STC-E-DEBUG-010`; actual type/shape/range failures are `STC-E-DEBUG-009`; unknown or
  non-writable targets are `STC-E-DEBUG-008`.
- **Boundary and forces.** `Host::cycle_at` latches inputs, substitutes active input forces after
  the latch, runs task guards and the module, applies queued writes in queue order, applies
  active forces in ascending `GotId` order, publishes outputs, and completes the cycle counter.
  A force wins over a same-cycle write, is re-applied every boundary, and is replaced by a second
  force as a new audited force. Release/release-all, session end, swap, rollback, cold install,
  and shutdown clear forces; queued entries are rejected with `STC-E-DEBUG-010` and never
  migrated. Force state is host memory only and is never written to `.stc-state`. A forced
  `RETAIN` root carries `STC-W-DEBUG-005`. Direct input/output writes and 1-bit BOOL writes use
  the active binding and preserve sibling bits.
- **Audit sink.** The engine exposes an `AuditSink` hook that receives Debug and Monitoring
  §13.3 format-1 event objects for writes, forces, replacements, releases, policy denials, end-of-
  debug-state clearing, and swap/session end. Events carry sequence, nullable time/session/scope
  placeholders, target, typed value, generation, build, cycle, outcome, and detail; values over
  4 KiB become `{"truncated":true,"size":N}`. The sink is optional in phase 4; a sink error
  refuses the audited write/force with `STC-E-DEBUG-021` (fail closed). Phase 5 supplies the
  JSONL file, protocol/session scopes, and authentication; phase 4 provides host-level clearing
  and the sink abstraction only.
- **Tests.** Added `crates/stc-got/tests/metadata_v2.rs` for format/domain constants, binary/JSON
  round-trip, canonical ordering, format-1 rejection, catalog/build-ID coverage, and malformed
  metadata. Added a `module_artifacts` codegen test for enum/subrange/program-aggregate
  projection and manifest round-trip. Added `crates/stc-runtime/tests/debug_write.rs` for queue
  order, boundary-only application, typed/range/enum/subrange/string/array validation,
  writability rejection, force replacement/release/release-all/force-wins, input-force latch,
  output-force publication, direct and bit writes, limits, swap/cold/activation/rollback/
  shutdown/clear rejection,
  audit sequence/typed values/truncation/swap-end, RETAIN warning, and host-level clearing.
  Existing phase-3 and workspace suites remain green; manifest/descriptor snapshots were updated
  only for format 2.

Deviations and limits recorded:

- Phase 4 adds no protocol, session, authentication, audit-file, rate-limit, breakpoint/step/
  call-stack, split-object presentation, or `stc debug` CLI surface. `AuditSink` is a host hook,
  not the phase-5 JSONL file, and session/scope/time fields remain null or zero placeholders.
- A queued write or force is rejected when debug state ends (swap/rollback/cold install/
  shutdown) before it is applied; because every generation change clears debug state, there is
  no public path for a queued entry to survive into a different generation. Application-time
  revalidation still checks generation/build, root existence, key/type/layout identity, expected
  values, writability, storage size, and direct bindings defensively.
- Writable roots are intentionally narrow: scalar, enum, subrange, alias, string, and single-root
  array values with their own persistent root. Aggregate/class/interface parent values and
  `OVERLAP`/reference/pointer values are rejected; individual scalar fields remain writable when
  the manifest gives them their own root. This avoids inventing identities for split storage.
- The host queue-result ring holds at most 1024 results, reusing the §13.5 queue bound; phase 5
  owns protocol delivery/backpressure. Force/queue state is not serialized, and a forced value
  visible in normal root storage at shutdown is subject only to the ordinary state-save policy;
  the force table itself never persists.
- Finite REAL/LREAL audit values use a raw JSON number token from the shared JSON model; the
  artifact canonical-JSON parser remains integer-only and rejects that token, so manifest
  determinism is unaffected. Non-finite values use `NaN`, `INF`, and `-INF`.
- Phase 5 should drive `Host::debug_service` and `Host::cycle_at` from its service/monitor
  thread, map `DebugQueueResult`/`AuditEvent` to protocol events and JSONL, and implement
  session-owned scope/rate/time fields without re-decoding storage. Phase 6 can reuse target
  resolution and stop-frame locals; phase 7 can reuse aggregate records for split presentation.
