# DIEWU 16I/16O loopback all-points test (WL-5.2 phase 6)

This project is the automated all-points functional matrix for the DIEWU
EtherCAT-IO 16I/16O fixture. It drives each output in turn, reads all 16
inputs through the bench loopback harness, records a per-channel pass/fail
mask, and exposes the result through the debug `var.read` surface.

It is a functional test of the module output drivers against the module input
optos. It is **not a safety function** and does not verify field devices,
isolation, input thresholds, or output load ratings.

The manual wiring, all-points, physical fault-injection, and evidence
procedure is in [PHASE6.md](../PHASE6.md). The open-ended phase 3-5 fixture
and its frame-level procedure are in [../README.md](../README.md).

## Wiring

The bench harness wires OUT1 to IN1 through OUT16 to IN16 (fixture channel N
is terminal N+1, so channel 0 is OUT1/IN1 and channel 15 is OUT16/IN16). Tie
the input commons S1, S2, S3, and S4 to the positive output supply. The
output supply may be 12 V or 24 V: it is inside the output DC5-48 V range and
the input 9-30 V range. The DIEWU outputs are NPN sinking and the input opto
is the load between S and IN, so a driven output reads back as a set input.

The full terminal table, supply/commons checklist, and harness limitations are
in [PHASE6.md](../PHASE6.md). Do not connect field loads to the loopback
bench.

## Process-image map

```
%IX0.0..%IX0.7  In0..In7     0x3001:01 bits 0..7
%IX1.0..%IX1.7  In8..In15    0x3001:02 bits 0..7
%QX0.0..%QX0.7  Out0..Out7   0x3101:01 bits 0..7
%QX1.0..%QX1.7  Out8..Out15  0x3101:02 bits 0..7
```

Status variables occupy `%I` bytes 4..38, the same addresses as the
open-ended fixture (`%IWn` is word n at byte 2n, `%IDn` is dword n at byte
4n). Bytes 2..3 are unused because this project has no PLC-in shadow
variable. The `ethercat-status` device fills the status block at the input
boundary; the fault procedure reads it through `var.read`.

## Test program

The program has four phases in the global `Phase`:

1. Warmup: all outputs off for 20 scans after the slave reaches OP.
2. Drive and settle: drive `Out0..Out15` one-hot for the current `Channel`,
   then wait 20 scans (20 ms at 1 ms).
3. Sample: read all 16 inputs into `InputMask`. Channel N passes when
   `InputMask` equals exactly `SHL(WORD#1, N)`: IN(N+1) reads 1 and every
   other input reads 0. Otherwise bit N of `FailMask` is set.
4. Done: drive all outputs off, latch `Pass := FailMask = WORD#0`, set
   `Done`.

`ObservedMask` records the channels whose own input was high at their
sample, so a stuck-high input and a dead output are distinguishable in the
diagnostics. `OutputMask` mirrors the 16 outputs the program drives. The
globals are readable with `var.read` on `DIEWU-LOOPBACK::NAME`.

`Hold` is FALSE in the all-points run. When the fault procedure sets it
through `var.write` after `Done`, the walk stops advancing and all 16 outputs
are driven on, so the held output image and the last received input image can
be observed while a physical fault is injected. The procedure sets it back to
FALSE before closing the session.

## Running the automated matrix

Deploy the fixture as described in [../README.md](../README.md), then run on
`ecat-host` as the login user (not root, no `--rt`):

```sh
export STC_ETHERCAT_LIBRARY="$HOME/stc-wl52/lib/libstc_io_ethercat.so"
export LD_LIBRARY_PATH="/usr/local/etherlab/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export PATH="$HOME/stc-wl52/bin:$PATH"

set -o pipefail
bash ~/stc-wl52/diewu/loopback/run-loopback.sh \
  2>&1 | tee ~/stc-wl52/logs/loopback-$(date +%Y%m%dT%H%M%S).log
```

`run-loopback.sh` builds the project once, then `loopback_test.py` launches
`stc debug` with the packaged compiler/runtime, polls `DONE` through
`var.read`, and prints the matrix. A healthy all-wired run ends with:

```
channel  output  input  expected  observed  result
-------  ------  -----  --------  --------  ------
      0  OUT1    IN1    1         1         PASS
      ...
     15  OUT16   IN16   1         1         PASS

Pass:          True
FailMask:      0x0000
ObservedMask:  0xFFFF
OutputMask:    0x0000 (outputs are off after the walk)
Channel:       16 (16 means every channel was sampled)
Acceptance:    PASS (16/16 channels; fieldbus healthy)
```

Exit codes: 0 when all 16 channels passed and the fieldbus status is healthy
(`faults=0`, `input.stale=false`, `wc_state=2`, link up, slave operational);
1 for a failed channel or an unhealthy fieldbus; 2 for a build, debug-channel,
or timeout error. The harness prints the failing mask and status, and the log
should be kept with the run evidence.

The harness defaults to `--io ethercat` and never passes `--rt`. Its
`--io memory` option exists only for an offline smoke test of the script on a
workstation; it is not phase-6 evidence and does not exercise the DIEWU.

## Limitations

- The loopback proves only that each output driver can turn on the corresponding
  input opto. It does not prove output load capacity, input threshold margins,
  isolation, cable/connector integrity outside the bench harness, or any field
  device.
- The DIEWU output watchdog is enabled. While the EtherCAT link or slave power
  is lost, the slave turns its outputs off even though the runtime keeps the
  last PLC output image unchanged. The physical output state during a fault is
  therefore not evidence of a runtime rewrite; the fault procedure reads the
  runtime image through `var.read` and the status registers.
- The test runs at 1 ms in a debug build without real-time scheduling. It is a
  functional check, not a timing measurement.
- This is not a safety function and does not implement a fail-safe output
  state.
